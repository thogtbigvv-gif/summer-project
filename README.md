# summer-project

Хувийн статусын цонх. Хэрэглэгчийн бие, оюун, бүтээлийн байдлыг **зөвхөн
бодит нотолгооноос** гаргаж харуулна.

Энэ бол RPG маягийн харагдацтай ч, RPG-ийн эдийн засаггүй систем. **XP байхгүй.
Түвшин байхгүй. Хадгалагдсан оноо байхгүй.** Дэлгэц дээрх тоо бүр — 100%, S тиер,
25 өдрийн цуврал — бүгд холбогдсон аппуудын явуулсан бичлэгээс тэр агшинд
дахин тооцогдсон байдаг.

---

## Гол дүрэм

Энэ дөрвөн дүрэм бол системийн өөрийн гэсэн онцлог. Бусад бүх шийдвэр
эдгээрээс урган гардаг.

### 1. Гаргалт хадгалалтыг ялгана

Нотолгоо (`webData.integrations[app].evidence`) бол цорын ганц үнэн. Дээд
давхаргын тоо БҮГД түүнээс гаргагдана — гаргасан үр дүнг буцааж хадгалахгүй.

Тиймээс **дүрэм буруу байвал нэг мөр засахад БҮХ ТҮҮХ буцаж зөв болно.**
Тиерийн хил, зорилтын хэмжээ, атрибутын томьёо — аль нь ч өөрчлөгдөхөд
өнгөрсөн жилийн тоо шууд дагаж засагдана. Гаргасан тоог хадгалбал яг энэ
шинж чанар үхнэ.

`status.js` бол цорын ганц гаргах давхарга. Тэр `webData` руу **юу ч бичихгүй**,
`saveWebData()`-г **хэзээ ч дуудахгүй**. Түүний ганц төлөв нь санах ойн кэш,
тэр нь ямар ч үед хаягдаж болно.

### 2. Тоо бүр бодит нэгжтэй

Систем `"42,000 kg"`, `"1,600 cards"`, `"10 commits"` гэж ярина. `"+250 XP"` гэж
**хэзээ ч** ярихгүй. Хувь гэдэг нь зөвхөн нэг утгатай: *"30 хоногийн бодит
зорилтод хэр ойрхон вэ"*.

### 3. Батлагдсан ба батлагдаагүйг ХЭЗЭЭ Ч хольж хутгахгүй

Даалгавар метрикт холбогдож зорилт зарлаж чадна. Тэгмэгц биелэлтийг нь
**хэн ч дарахгүй** — нотолгоо шийднэ. Тийм даалгаварт "БИЕЛҮҮЛЭХ" товч
байхгүй нь алдаа биш, гол санаа нь тэр.

Гараар тэмдэглэх нь ч бас нотолгоо үүсгэдэг — гэхдээ **тусдаа**:

| | Хэн хэлсэн | Хаана орох |
|---|---|---|
| Аппын нотолгоо | Bigu, Gym, GitHub | `BODY` · `MIND` · `CREATION` |
| Өөрөө мэдээлсэн | Хэрэглэгч өөрөө | `DISCIPLINE` (зөвхөн энд) |

Өөрөө тэмдэглэсэн зүйл `BODY`-г **хэзээ ч** хөдөлгөхгүй: дасгал хийсэн гэж
дарахад кг үүсэхгүй. Тэр нь `DISCIPLINE` буюу "би өөрөө хийсэн гэж хэлсэн"
гэсэн тусдаа тэнхлэгт л ордог бөгөөд Integrity самбарт `ӨӨРӨӨ` гэж
тэмдэглэгддэг. Дарж хуурах боломж системд ЯГ НЭГ л газар байгаа бөгөөд тэр
нь ил байна.

Тэр цорын ганц газар цааш ТАРАХГҮЙ байх ёстой. Өөрөө мэдээлдэг метрикийг
(`selfReported: true`) даалгавар, ур чадварын "нотолгооны эх сурвалж"
сонголтод **гаргахгүй** — эс тэгвээс "нотлогдсон" даалгавар зарлаад түүнийгээ
өөрөө дарж биелүүлэх зам нээгдэнэ. `verifiableMetricIds()` тэр шүүлтийг
нэг л газар хийдэг.

**Нэгтгэсэн тоо ч мөн адил.** Метрик бүр хэн хэлснээ зөөж байхад
"нийт нотолгоо", "30 хоногийн идэвхтэй өдөр" гэсэн НЭГТГЭЛ хоёуланг нь нэг
саванд хийдэг байв. Тэр нь ердөө нэг талбарын алдаа биш: профайлын оноог
үүрч буй **жин**, аналитикийн `CONSISTENCY` хоёр яг эндээс гардаг тул ганц ч
апп холбоогүй хүн өдөр бүр нүд даран `100%` харах боломжтой байсан. Өөрөө
өөрийгөө баталсан жин бол жин биш.

| `overall`-ын талбар | Юуг тоолох | Хаана харагдах |
|---|---|---|
| `totalEvents` · `activeDays30` · `firstEvidenceAt` | **зөвхөн гадны апп** | Профайлын үндэс · `ACTIVE DAYS` · `CONSISTENCY` |
| `overall.self.*` | **зөвхөн өөрөө дарсан** | Тэдний доор, `ӨӨРӨӨ МЭДЭЭЛСЭН` нэрээр, шар өнгөөр |
| `overall.anyEvents` | хоёулаа | ЗӨВХӨН "дэлгэц хоосон юу" гэдгийг шийдэхэд |

`anyEvents` бол **хэмжилт биш, туг**. Түүнийг тоо болгон дэлгэц дээр гаргах
нь яг одоо хаагдсан нүхийг буцааж нээнэ.

Батлагдсан нотолгоо тэг байхад check-in байвал дэлгэц тэр тоог **нөхөхгүй** —
`БАТЛАГДСАН НОТОЛГОО 0` гээд, доор нь *"Дээрх оноог ямар ч апп батлаагүй
байна"* гэж шалтгааныг нь хэлнэ. Тоо тэг байх ба тоо байхгүй байх хоёр өөр.

### 4. Чимээгүй алдахгүй

Нотолгоо тасрах нь дэлгэц дээр "би сул дорой байна" мэт харагдах ёсгүй. Тиймээс:

| Юу тасарсан | Хаана харагдах |
|---|---|
| Эх сурвалж чимээгүй болсон | `EVIDENCE CHAIN // INTEGRITY` → `ТАСАРСАН` |
| Танигдаагүй event төрөл | Тэр самбарын анхааруулга + дүгнэлт, **хэдэн бичлэг ороогүйг тоогоор** |
| Нэгжээ сэргээж чадаагүй нэгтгэл | Мөн тэнд, хэдэн бичлэг гээгдсэнийг тоогоор |
| Хадгалалт дүүрэх гэж байна | Мөн тэнд — **дүүрэхээс өмнө**, шар анхааруулга |
| Хадгалалт дүүрсэн | Мөн тэнд, улаанаар: шинэ нотолгоо бичигдэхээ больсон |
| Оноог ямар ч апп батлаагүй | Профайлын үндэс → `БАТЛАГДСАН НОТОЛГОО 0` + шалтгаан |
| Тоо хаанаас гарсан нь ойлгомжгүй | Ур чадвар/даалгаврын modal → `НОТОЛГОО` жагсаалт |

Анхааруулга бүр **хэмжээтэйгээ** гарна. `gym:sauna.session танигдсангүй` гэдэг
нь 3 бичлэг ч байж болно, 3000 ч байж болно — тэр хоёр тэс өөр яаралтай
байдалтай атлаа нэрнээс нь ялгагдахгүй. Тиймээс танигдаагүй төрөл бүр
**хэдэн бичлэг статуст ороогүй**, **хэзээ сүүлд ирснийг** хамт хэлнэ.

Нотолгоо огт байхгүй бол систем **тэг** гэж хэлнэ. Тоо зохиохгүй, алдаа ч шидэхгүй.

## Гүүрийн гэрээ

Холбогдсон апп бүр ижилхэн JSON нийтэлнэ:

```jsonc
{
  "v": 1,
  "updatedAt": 1787374324442,
  "status": { /* апп юу ч хүсвэл — бид бүтнээр нь хадгална, тайлбарлахгүй */ },
  "events": [
    {
      "id":     "gym:2026-08-21:push",   // ЗААВАЛ. Давхардлын хамгаалалт үүн дээр тогтоно
      "at":     1787374324442,           // ms
      "type":   "workout.completed",
      "value":  1,
      "detail": "Push day",
      "data":   { "volumeKg": 4200 }     // заавал биш: бодит нэгж энд
    }
  ]
}
```

Түлхүүр байхгүй, JSON гэмтсэн, эсвэл `v !== 1` бол тэр эх сурвалжийг **чимээгүй
алгасна** — апп өнөөдрийнхтэй яг адилхан ажиллана.

**Гурван төрлийн хүргэлт, нэг гэрээ:**

- `kind: "local"` — ижил origin дээрх апп `localStorage`-д бичнэ.
- `kind: "fetch"` — repo дотор commit хийгдсэн JSON. GitHub `localStorage` руу
  бичиж чадахгүй тул түүний нотолгоо Action-аар дамжиж `data/github.json`
  болж ирдэг.
- `kind: "self"` — **гадны апп биш**. Хэрэглэгч өдрийн даалгавраа тэмдэглэхэд
  энэ апп өөрөө бичдэг. Уншиж авах фийд байхгүй тул `syncAll()` алгасна.

## Өдрийн даалгавар

Даалгавар бүр `metricId` зарлаж болно. Түүнээс хойш хоёр зам:

```
                     тэр метрикт ӨНӨӨДӨР нотолгоо ирсэн үү?
                                   │
                 тийм ─────────────┴───────────── үгүй
                   │                                │
        ✓ НОТЛОГДСОН                        дарж болно
        (дарах юм байхгүй)                        │
        Gym → 4,200 kg                    ◈ ӨӨРӨӨ МЭДЭЭЛСЭН
                                          self.checkins → DISCIPLINE
```

Дасгал хийгээд Gym аппаа нээхэд "Workout" даалгавар **өөрөө** ✓ болно — хэн ч
дарах шаардлагагүй. Харин "2 литр ус уух" гэдгийг ямар ч апп мэдээлдэггүй тул
түүнийг дарж бүртгэнэ, тэр нь `DISCIPLINE`-д л ордог.

Тэмдэглэгээ нь `task.completed` талбараас БИШ, **нотолгооноос** гардаг:
бичлэгийн id нь `self:<taskId>:<өдөр>` тул нэг өдөр нэг даалгавар яг нэг удаа
тоологдож, буцааж авахад яг тэр бичлэг устна. Хуучин өдрийн бүртгэл түүх болж
үлдэнэ — өдөр солигдоход зүгээр л шинэ өдрийн id хайгдана.

Даалгаврыг самбар дээрээс нэмж, хасаж болно. **Хасах нь түүх устгахгүй**:
өмнө нь бүртгэсэн check-in-ууд нотолгоо хэвээр үлдэнэ, учир нь тэдгээр нь
үнэхээр болсон явдал байсан. Жагсаалт бол өнөөдрийн санаа, нотолгоо бол
өнгөрсний баримт — хоёр өөр зүйл.

Товч, гар хоёулаа ажиллана (`Enter` / `Space`): DISCIPLINE-ыг хөдөлгөдөг
цорын ганц удирдлагыг зөвхөн хулганаар хүрч болдог байлгах нь бүхэл нэг
тэнхлэгийг нууж байгаатай адил.

## Өргөтгөх

Эх сурвалж холбох ХОЁР зам бий: **дэлгэцээс** (код хөндөхгүй) ба **кодоос**
(суурь жагсаалтад). Хоёулаа ЯГ ИЖИЛ гэрээгээр дамжина.

### Дэлгэцээс холбох (код хөндөхгүй)

Статус таб → «Холбогдсон Аппууд» → **+ Эх сурвалж холбох**. Нэр, төрөл
(`localStorage` түлхүүр эсвэл JSON файлын хаяг), түлхүүр/хаягаа өгнө.

**Шалгах** товч нь хадгалахаас ӨМНӨ уншиж үзээд юу олдсоныг хэлнэ: хэдэн
бичлэг, ямар төрлүүд, хэзээ шинэчлэгдсэн. Буруу түлхүүр бичсэн хүн түүнийгээ
хадгалсны дараа биш, яг тэр агшинд мэднэ.

Холбосны дараа карт дээр **төрөл бүрийг метрикт холбоно**. Үүнгүйгээр
нотолгоо нь хадгалагдах ч ямар ч тоо гаргахгүй — карт үүнийг шууд хэлнэ
(*"N төрөл тоо гаргахгүй байна"*). Гурван дүрмээс сонгоно:

| Дүрэм | Тоог хаанаас авах | Нэгтгэсэн хувингаас |
|---|---|---|
| `count` | бичлэг бүр 1 | `count` |
| `value` | `event.value` | `valueSum` |
| `data`  | `event.data.<түлхүүр>` | `dataSums.<түлхүүр>` |

Гурвуулаа 180 хоногийн дараа нэгтгэгдсэн ч **бодит нэгжээ алдахгүй**.

Метрикийг нь мөн адил дэлгэцээс үүсгэж болно (нэр, нэгж, атрибут, 30 хоногийн
зорилт). Атрибут нь `BODY` / `MIND` / `CREATION` — `DISCIPLINE`-ыг СОНГУУЛАХГҮЙ:
тэр бол "өөрөө мэдээлсэн" тэнхлэг бөгөөд гадны аппын батлагдсан тоог тийш нь
хийвэл батлагдсан ба батлагдаагүй хоёр нэг баганад холилдоно.

Хэрэглэгчийн холболт `webData.sources`, `webData.metrics`,
`webData.metricMap`-д **тохиргоо** болж сууна — гаргасан тоо биш. Дүрэм
өөрчлөгдвөл бүх түүх дагаж дахин тооцогдоно, яг кодод бичигдсэнтэй адил.

**Холбоо салгахад нотолгоо ҮЛДЭНЭ.** Жагсаалтаас хасах нь "уншихаа болих"
гэсэн үг, "түүхийг устгах" гэсэн үг биш.

### Холболт эрүүл эсэх

Карт бүр төлөвөө өөрөө хэлнэ: `ИДЭВХТЭЙ` · `ЧИМЭЭГҮЙ` · `ХҮЛЭЭГДЭЖ БАЙНА` ·
`ФИЙД ГЭМТСЭН` · `ХҮРЭХГҮЙ БАЙНА` · `ГАР БҮРТГЭЛ`. Бүтэлгүйтэл бүр
шалтгаанаа нэрлэнэ — түлхүүр олдсонгүй, JSON биш, `v≠1`, HTTP 404, сүлжээ.
Урьд нь эдгээр бүгд `null` байсан: карт зүгээр л бүдгэрч, хүн ЯЛГАХ АРГАГҮЙ
байв.

Шалгалтын үр дүн нь **санах ойд** л амьдарна (`bridgeChecks`) — Status-ийн
кэштэй ижил зарчим. Хадгалбал минут тутмын синк бүр бүх датаг дахин бичиж,
утсан дээр дэмий ажиллагаа үүсгэнэ.

`↻ Дахин унших` — карт тус бүрд, `↻ Бүгдийг унших` — самбарын толгойд.
Автомат синк (focus / таб харагдах / минут тутам) хэвээрээ.

### Кодоос холбох (суурь жагсаалт)

`bridge.js` → `BRIDGE_SOURCES`-д **нэг мөр**:

```js
{ app: "duolingo", kind: "local", key: "duo:bridge", label: "Duolingo", hex: "#58cc02" }
```

Өөр код бичихгүй. Синк, хадгалалт, "Connected" карт, бүрэн бүтэн байдлын
самбар — бүгд өөрсдөө дагана.

### Шинэ метрик нэмэх

`status.js` → хоёр хүснэгтэд мөр нэмнэ:

```js
// Event-ийн төрөл юу гэсэн утгатайг ТАЙЛБАРЛАДАГ цорын ганц газар
"duolingo:lesson.done": {
    metric:     "duo.xp",
    amount:     e => num(e.value),        // түүхий бичлэгээс
    fromRollup: b => num(b.valueSum)      // нэгтгэсэн хувингаас, ижил нэгжээр
},

// Метрик өөрөө: нэр, нэгж, аль атрибутад харьяалагдах, 30 хоногийн зорилт
"duo.xp": { label: "Duolingo XP", unit: "xp", attr: "MIND", target30: 3000 }
```

Ур чадвар болон даалгаврын формын "Нотолгооны эх сурвалж" сонголт нь энэ
бүртгэлээс баригддаг тул тэнд ч юу ч засахгүй.

`fromRollup` нь `null` буцаах эрхтэй = *"энэ хувингаас бодит нэгжийг сэргээх
аргагүй"*. Тэр үед 0 нэмэгдэнэ, **гэхдээ чимээгүй биш**: `overall.rollupGaps`-д
бүртгэгдээд Аналитик таб дээр хэдэн бичлэг гээгдсэнийг тоогоор хэлнэ.

## Нотолгоог алдахгүй байх

Систем нотолгоог "цорын ганц үнэн" гэж зарладаг. Тэгвэл түүнийг ганц
браузерын `localStorage` дотор, ганц хуулбартай байлгах нь тэр зарлалыг
хоосон болгоно. Үйлдвэрлэгч аппууд ердөө **сүүлийн 50 event**-ээ хадгалдаг
тул устсан бичлэг **эргэж ирэхгүй**.

### Гаргах / сэргээх

`НОТОЛГОО ЭКСПОРТЛОХ` нь бүх датаг JSON файл болгон татна. `НӨӨЦӨӨС СЭРГЭЭХ`
нь түүнийг буцааж уншина — **нэгтгэж**, дарж бичихгүй:

| Юу | Хэрхэн нийлдэг | Яагаад |
|---|---|---|
| Түүхий бичлэг | `id`-гаар нэгтгэнэ | id тогтвортой тул давхардал үүсэхгүй |
| `prunedBefore`-оос хуучин | **алгасна** | тэр event аль хэдийн хувин болсон — оруулбал хоёр удаа тоологдоно |
| Нэгтгэсэн хувин | `count` илүү ихийг нь авна | нэмбэл давхар тоолно; илүү ихийг харсан тал нь бүрэн |
| Жагсаалт, ангилал | файлынхаар солино | жагсаалтыг дахин бичихэд амархан, нотолгоог сэргээх аргагүй |

Хувин нэгтгэх дүрэм нь **дутуу тоолж магадгүй** (хоёр төхөөрөмж өөр өөр event
харсан бол). Тэр нь зориуд: дутуу тоолох нь давхар тоолохоос үргэлж дээр —
систем тоо зохиодоггүй.

### Хоёр өөр "цэвэрлэх"

| Товч | Юу устгах | Сэргээгдэх үү |
|---|---|---|
| `ЖАГСААЛТ ЦЭВЭРЛЭХ` | Даалгавар, ур чадвар, ангилал, өдрийн жагсаалт | Нотолгоо **хэвээр** |
| `НОТОЛГОО ХАМТ УСТГАХ` | Бүгд | **Үгүй** — тоог нь нэрлэсэн хоёр баталгаажуулалт асууна |

Өмнө нь ганцхан RESET товч байсан бөгөөд тэр нь нэг `confirm()`-ын цаана бүх
түүхийг үүрд устгадаг байв.

### Хадгалалтын тааз

4 эх сурвалж × 5000 түүхий бичлэг ≈ 3–4MB, `localStorage` нь ~5MB. Өөрөөр
хэлбэл "хэзээ ч хаяхгүй" гэсэн бодлого таазтай **зайлшгүй мөргөлдөнө**.

**"Дүүрэв" гэж хэлэх нь аль хэдийн оройтсон байдаг.** `setItem` унасан
агшинд яг тэр бичлэг алдагдсан бөгөөд үйлдвэрлэгч апп ердөө сүүлийн 50
event-ээ хадгалдаг тул **эргэж ирэхгүй**. Систем "чимээгүй алдахгүй" гэсэн
амлалтаа биелүүлж байгаа ч нэг бичлэг хожимдсон байна.

Тиймээс дарамтыг **урьдчилан** хэмждэг: `storagePressure()` нь сүүлд
хадгалсан бодит хэмжээг ердийн таазтай харьцуулна (ачаалах үед л уншсан
хэмжээгээр эхэлнэ — эхний хадгалалтыг хүлээхгүй).

| Түвшин | Хэзээ | Дэлгэц |
|---|---|---|
| `ok` | 75%-иас доош | чимээгүй |
| `high` | 75%-иас дээш, **хараахан унаагүй** | шар анхааруулга + дүгнэлт: одоо экспортлоорой |
| `full` | `setItem` үнэхээр унасан | улаан анхааруулга: шинэ нотолгоо хадгалагдахгүй байна |

Гарц нь хоёр түвшинд ижил: экспортлох → нотолгоо хамт устгах → шаардлагатай
бол файлаа сэргээх. Ялгаа нь **хэзээ** хийх вэ гэдэгт: `high` дээр хийвэл
юу ч алдагдахгүй, `full` дээр хийвэл хэдэн бичлэг аль хэдийн алдагдсан.

## Нотолгооны хадгалалт

Бичлэгийг **хэзээ ч зүгээр хаяхгүй** — дээд давхаргын бүх тоо түүнээс
гардаг тул хаях нь түүхийг устгахтай адил.

```
шинэ бичлэг ──► evidence[]  ──180 хоног──►  rollups["YYYY-MM"][type]
               (түүхий, өдрийн              { count, valueSum, dataSums,
                нарийвчлалтай)                firstAt, lastAt }
```

`dataSums` нь `event.data`-гийн **тоон талбар бүрийн нийлбэр**. Түүнгүйгээр
`data.volumeKg` дээр тулгуурладаг метрик (дасгалын кг) нэгтгэгдмэгц мөнхөд
0 болж хувирдаг байсан. Гүүр талбарууд юу гэсэн утгатайг мэдэхгүй хэвээр —
зөвхөн "тоо мөн үү" гэдгийг шалгана; утгыг нь тайлбарлах нь `status.js`-ийн ажил.

`rollups`-ыг **хэзээ ч устгахгүй**. `prunedBefore` нь зөвхөн өсдөг — эс тэгвээс
нэгтгэгдсэн event дахин "шинэ" мэт орж ирнэ.

## Утсан дээр суулгах (PWA)

Апп нь суулгагдах вэб апп. Утсанд нэмсний дараа нүүр дэлгэц дээр өөрийн
дүрстэй, хаягийн мөргүй, **сүлжээгүй үед ч нээгддэг** болно.

| Төхөөрөмж | Хэрхэн |
|---|---|
| **Android / Chrome** | Толгой дахь **⤓ Утсанд суулгах** товч, эсвэл хөтчийн цэс → «Апп суулгах» |
| **iPhone / Safari** | Хуваалцах ⎋ → «Нүүр дэлгэцэнд нэмэх» (Safari нь суулгах товчийг дэмждэггүй тул гар аргаар) |
| **Компьютер / Chrome** | Хаягийн мөрний баруун талын суулгах дүрс |

Нүүр дэлгэцийн дүрсийг удаан дарахад **Даалгавар** ба **Аналитик** руу шууд
үсрэх товчлол гарна (`manifest.webmanifest` → `shortcuts`).

### Утас бол жижигрүүлсэн хувилбар биш

Апп нь нүүр дэлгэцээс хаягийн мөргүй нээгддэг тул олон хүний хувьд утас нь
**цорын ганц** хувилбар. Тиймээс 700px-ээс доош өргөнд зүгээр л "багтаах"
биш, өөрөөр өрнө.

| Юу | Ширээн дээр | Утсан дээр | Яагаад |
|---|---|---|---|
| Навигаци | Толгойд, нэг мөрөнд | **Доод самбар**, 4 тэнцүү багана, дүрстэй | Толгойд 4 таб багтахгүй болж 3+1 болон мултарч, товч тус бүр 28px өндөртэй байв — эрхий хурууны 44px талбайн гуравны хоёр ч биш |
| Толгой | Наалддаг | Наалддаггүй | Наалдах ганц шалтгаан нь навигаци байсан; тэр нь доошоо явсан |
| Даалгаврын жагсаалт | Форм зүүн баганад зэрэгцээ | **Жагсаалт эхэндээ**, форм ард нь | Хүн энэ табыг байгаа зүйлээ харах гэж нээдэг, шинэ нэмэх гэж биш |
| Өдрийн даалгавар | Нэр ба нотолгоо нэг мөрөнд | Нотолгоо нь нэрийнхээ доор | "Volume lifted 3,200 kg" гэсэн нотолгоо ирмэгээр тасарч, огт уншигдахгүй байв |
| Толгойн 4 тоо | Нэг мөр | **2×2** | Нэг баганаар өрөхөд карт бүр ~230px болж, ганц тоонд дэлгэцийн дөрөвний нэг зарцуулагдана |
| Халуун зураглал | 30×1 | **10×3** | Нэг эгнээнд нүд бүр ~10px болж, өнгөний ялгаа нь харагдахаа болино |
| Цонх | Голд хөвнө | **Доошоос гарах хуудас** | Голд хөвөх цонхны хаах товч дээд буланд үлдэж, эрхий хуруу хүрэхгүй |
| Доод үйлдлүүд | Баруун ирмэгт жижиг холбоос | Бүтэн өргөнтэй мөр | Устгах нь БУЦААГДАХГҮЙ — санамсаргүй хүрэх ёсгүй, гэхдээ олдохгүй байх ч ёсгүй |

Хоёр хэмжүүр тогтмол: **хүрэх зорилт 40px-ээс жижиг биш**, **үсэг 10px-ээс
жижиг биш**. Хулганы үзүүр 1px, эрхий хурууны талбай ~44px — ижил товч хоёр
төхөөрөмж дээр ижил хэмжээтэй байх ёсгүй.

> **Нэг ноцтой нарийн ширийн зүйл:** доод самбар нь `position: fixed` бөгөөд
> `.web-header` дотор сууна. Толгой нь `backdrop-filter`-тэй байсан бөгөөд тэр
> шинж чанар нь өөрийн дотор байгаа `fixed` элементэд **шинэ тулгуур хайрцаг**
> үүсгэдэг: `bottom: 0` гэдэг нь дэлгэцийн доод ирмэг биш, ТОЛГОЙН доод ирмэг
> гэсэн утгатай болж, самбар дэлгэцийн дээд талд наалддаг байв. Утсан дээр
> толгойн `backdrop-filter`-ийг авдаг нь тиймээс.

Таб солиход хуудас эхэндээ буцна — эс тэгвээс "Аналитик" дарсан хүн уг табын
дундаас нээгдэнэ. Аль хэдийн нээлттэй табаа дахин дарахад байрлал **үсрэхгүй**.

### Офлайн юу ажилладаг вэ

Бүх нотолгоо **аль хэдийн** localStorage-д сууж байгаа тул сүлжээнээс
хамаарч байсан цорын ганц зүйл бол бүрхүүл (HTML/CSS/JS) байв. `sw.js`
түүнийг суулгах агшинд кэшэлдэг болсон:

| Юу | Стратеги | Яагаад |
|---|---|---|
| Бүрхүүл (HTML/CSS/JS/icon) | Кэшээс шууд, ард нь шинэчилнэ | Нээлт нь агшин зуур; дараагийн ачаалалт шинэ |
| Навигац | Сүлжээ түрүүлнэ, эс бөгөөс кэш | Онлайн үед үргэлж шинэ; офлайнд хоосон дэлгэц гарахгүй |
| `data/github.json` | Сүлжээ түрүүлнэ | Хуучирсан нотолгоо **ХУДЛАА** статус өгнө. Офлайнд сүүлийн мэдэгдэж байсан нь |
| Фонт (Google) | Кэшээс шууд, ард нь шинэчилнэ | Офлайнд үсгийн хэв солигдож харагдац эвдрэхгүй |

Хараахан ирээгүй нотолгоо (холбогдсон аппуудын фийд) офлайн үед мэдээж
шинэчлэгдэхгүй — синк нь сүлжээ сэргэмэгц дараагийн нээлтэд явна.

### Шинэ хувилбар гаргах үед

Файлын нэрэнд hash байхгүй тул кэшийг **гараар** ахиулна: `sw.js` доторх
`VERSION`-ыг өсгөнө (`v1` → `v2`). Тэгэхгүй бол хуучин бүрхүүл кэшэндээ
үлдэж, суулгасан апп өдрөөр хоцорч болзошгүй.

Шинэ хувилбар бэлэн болмогц хэрэглэгчид жижиг мэдэгдэл гарч, **тэр
зөвшөөрсний дараа** л хуудас сэргэнэ — дунд нь өөрөө солигдвол бөглөж
байсан форм алдагдана.

> **Анхаар:** `index.html`-д шинэ `<script>` эсвэл `<link>` нэмбэл `sw.js`
> доторх `SHELL` жагсаалтад мөн нэмнэ. Мартвал апп ердийн үедээ ажиллаж
> байгаад **зөвхөн офлайн үед** хагас ачаалагдана — тэр алдаа хөгжүүлэлтийн
> үед хэзээ ч харагдахгүй. `tests/pwa.test.js` яг үүнийг барихаар суусан.

Ангиллын карт болон атрибутын мөр бүр **дарагдана**: тоо хаанаас гарсан
(нотолгооны мөрүүд), 30 хоногийн чиг хандлага, зорилт, цуврал, хамгийн сайн
өдөр, мөн **түүнийг тэжээж буй эх сурвалж эрүүл эсэх** нэг цонхонд гарна.
"Тоо зогссон" гэдэг ихэвчлэн "апп чимээгүй болсон" гэсэн үг — хоёрыг нь
тусад нь харуулах нь хэрэглэгчийг өөрөө таамаглуулж байгаа хэрэг.

## Хөгжүүлэх

Build алхам байхгүй, хамаарал байхгүй. Энгийн статик файлууд.

```bash
# Дотоод сервер (bridge.js data/github.json-ыг татдаг тул file:// болохгүй)
python3 -m http.server 8000

# Тест — зөвхөн Node хэрэгтэй
node tests/run.js
```

Service worker нь `http://localhost` дээр ажиллана (өөр домэйнд HTTPS
шаардлагатай). Хөгжүүлэх үед хуучин кэш саад болвол DevTools →
Application → Service Workers → *Update on reload*.

Тест нь нотолгооноос тоо гаргах болон нотолгоо хадгалах давхаргыг хамарна.
Тэр хоёрын дүрэм өөрчлөгдөхөд **бүх түүх дагаж өөрчлөгддөг** тул алдаа нь
чимээгүй бөгөөд хожим эргэж баригдахгүй — тиймээс л тэдэнд тест бий.

| Файл | Юуг хамгаалах |
|---|---|
| `derive.test.js` | Нотолгоо → бодит нэгж, нэгтгэсэн хувингаас сэргээх, зорилт |
| `durability.test.js` | Экспорт / сэргээлт, хоёр төрлийн цэвэрлэгээ |
| `migration.test.js` | Хуучин хадгалагдсан датаг ЭВДЭХГҮЙГЭЭР шилжүүлэх |
| `mission.test.js` · `quests.test.js` | Даалгавар: нотлогдсон ба өөрөө мэдээлсэн зам |
| `provenance.test.js` | **Хэн хэлсэн бэ**: нэгтгэсэн тоонд хольц үүсэхгүй, танигдаагүй төрлийн хэмжээ, хадгалалтын дарамт — мөн эдгээр нь дэлгэц дээр үнэхээр гарч байгаа эсэх |
| `pwa.test.js` | Офлайн бүрхүүлийн жагсаалт `index.html`-ээс хоцроогүй эсэх |
| `sources.test.js` | Эх сурвалж холбох, оношилгоо, төрөл → метрик |

`provenance.test.js` нь гаргалтын давхаргыг шалгаад зогсохгүй **рендерийг**
ч дуудна: ялгаа гаргалтад зөв байлаа ч дэлгэц дээр нэг мөр мартагдвал
хэрэглэгчийн хувьд юу ч өөрчлөгдөөгүй. Бүрэн бүтэн байдлын самбар нь яг
"чимээгүй эвдрэлийг олж хэлэх" үүрэгтэй тул тэр өөрөө чимээгүй эвдэрч
болохгүй.

| `sw.js` | Офлайн кэш: precache + гурван стратеги. Хувилбарыг гараар ахиулна. |
| `manifest.webmanifest` | Суулгах гэрээ: нэр, icon, эхлэх зам, товчлол. |
| `icons/` | `icon.svg` эх сурвалж + түүнээс гаргасан PNG (192/512/maskable/apple). |
| `.github/workflows/` | Pages deploy · өдөр тутмын GitHub нотолгоо · тест. |

### Юу байхгүй вэ (зориудаар)

`logDailyActivity()`, `addGlobalXp()`, `advanceCategoryTier()` — эдгээр нэгэнтээ
байсан, устгагдсан. Түвшин, цол, мастери, тиерийн XP гэсэн ойлголт энэ кодын
баазад **байхгүй**. Дуудагчгүй үлдсэн ч гэсэн буцаж холбогдох зам нээлттэй
байх ёсгүй тул функцүүдийг нь бүрмөсөн авсан.
