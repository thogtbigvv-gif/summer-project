# summer-project

Хувийн статусын цонх. Хэрэглэгчийн бие, оюун, бүтээлийн байдлыг **зөвхөн
бодит нотолгооноос** гаргаж харуулна.

Энэ бол RPG маягийн харагдацтай ч, RPG-ийн эдийн засаггүй систем. **XP байхгүй.
Түвшин байхгүй. Хадгалагдсан оноо байхгүй.** Дэлгэц дээрх тоо бүр — 100%, S тиер,
25 өдрийн цуврал — бүгд холбогдсон аппуудын явуулсан бичлэгээс тэр агшинд
дахин тооцогдсон байдаг.

---

## Гол дүрэм

Энэ дөрвөн дүрэм бол системийн өөрийн гэсэн онцлог. Бусад бүх шийдвэр
эдгээрээс урган гардаг.

### 1. Гаргалт хадгалалтыг ялгана

Нотолгоо (`webData.integrations[app].evidence`) бол цорын ганц үнэн. Дээд
давхаргын тоо БҮГД түүнээс гаргагдана — гаргасан үр дүнг буцааж хадгалахгүй.

Тиймээс **дүрэм буруу байвал нэг мөр засахад БҮХ ТҮҮХ буцаж зөв болно.**
Тиерийн хил, зорилтын хэмжээ, атрибутын томьёо — аль нь ч өөрчлөгдөхөд
өнгөрсөн жилийн тоо шууд дагаж засагдана. Гаргасан тоог хадгалбал яг энэ
шинж чанар үхнэ.

`status.js` бол цорын ганц гаргах давхарга. Тэр `webData` руу **юу ч бичихгүй**,
`saveWebData()`-г **хэзээ ч дуудахгүй**. Түүний ганц төлөв нь санах ойн кэш,
тэр нь ямар ч үед хаягдаж болно.

### 2. Тоо бүр бодит нэгжтэй

Систем `"42,000 kg"`, `"1,600 cards"`, `"10 commits"` гэж ярина. `"+250 XP"` гэж
**хэзээ ч** ярихгүй. Хувь гэдэг нь зөвхөн нэг утгатай: *"30 хоногийн бодит
зорилтод хэр ойрхон вэ"*.

### 3. Батлагдсан ба батлагдаагүйг ХЭЗЭЭ Ч хольж хутгахгүй

Даалгавар метрикт холбогдож зорилт зарлаж чадна. Тэгмэгц биелэлтийг нь
**хэн ч дарахгүй** — нотолгоо шийднэ. Тийм даалгаварт "БИЕЛҮҮЛЭХ" товч
байхгүй нь алдаа биш, гол санаа нь тэр.

Гараар тэмдэглэх нь ч бас нотолгоо үүсгэдэг — гэхдээ **тусдаа**:

| | Хэн хэлсэн | Хаана орох |
|---|---|---|
| Аппын нотолгоо | Bigu, Gym, GitHub | `BODY` · `MIND` · `CREATION` |
| Өөрөө мэдээлсэн | Хэрэглэгч өөрөө | `DISCIPLINE` (зөвхөн энд) |

Өөрөө тэмдэглэсэн зүйл `BODY`-г **хэзээ ч** хөдөлгөхгүй: дасгал хийсэн гэж
дарахад кг үүсэхгүй. Тэр нь `DISCIPLINE` буюу "би өөрөө хийсэн гэж хэлсэн"
гэсэн тусдаа тэнхлэгт л ордог бөгөөд Integrity самбарт `ӨӨРӨӨ` гэж
тэмдэглэгддэг. Дарж хуурах боломж системд ЯГ НЭГ л газар байгаа бөгөөд тэр
нь ил байна.

Тэр цорын ганц газар цааш ТАРАХГҮЙ байх ёстой — хоёр замаар:

**Сонголтод гаргахгүй.** Өөрөө мэдээлдэг метрикийг (`selfReported: true`)
даалгавар, ур чадварын "нотолгооны эх сурвалж" сонголтод оруулахгүй — эс
тэгвээс "нотлогдсон" даалгавар зарлаад түүнийгээ өөрөө дарж биелүүлэх зам
нээгдэнэ. `verifiableMetricIds()` тэр шүүлтийг нэг л газар хийдэг.

**Нэгтгэсэн тоонд ч барина.** Ялгааг зөвхөн атрибутын түвшинд барих нь
хангалтгүй. `BODY/MIND/CREATION` цэвэр хэвээр байхад толгойн тоонууд
өөрөө мэдээлсэнийг хамт тоолж байвал өдөрт гурван нүд дарж л `CONSISTENCY`
100% болгож болно — дарж хуурах боломж өөр хаалгаар буцаж орно. Тиймээс:

| Тоо | Юуг тоолдог |
|---|---|
| `ACTIVE DAYS` · `CONSISTENCY` | `overall.proven` — зөвхөн гадны эх сурвалж |
| `TRACKED METRICS` · `LONGEST STREAK` | `provenMetrics()` — `selfReported` метрикгүй |
| Профайлын `НОТЛОГДСОН` / `ӨӨРӨӨ БҮРТГЭСЭН` | хоёр тусдаа мөр |
| `ӨНӨӨДРИЙН НОТОЛГОО` | зөвхөн батлагдсан метрик |
| Халуун зураглалын **ногоон** | зөвхөн батлагдсан; өөрөө тэмдэглэсэн өдөр **алтан хүрээтэй** |

`overall.activeDays30` / `overall.totalEvents` нь нийлбэр хэвээр үлдэнэ —
"ямар нэг юм болсон уу" гэдэгт хариулах учиртай. Толгойн тоо түүнээс биш,
`overall.proven`-оос уншина.

### 4. Чимээгүй алдахгүй

Нотолгоо тасрах нь дэлгэц дээр "би сул дорой байна" мэт харагдах ёсгүй. Тиймээс:

| Юу тасарсан | Хаана харагдах |
|---|---|
| Эх сурвалж чимээгүй болсон | `EVIDENCE CHAIN // INTEGRITY` → `ТАСАРСАН` |
| Фийд байгаа мөртлөө уншигдахгүй | Мөн тэнд → `УНШИГДАХГҮЙ`, шалтгаан нь нэрлэгдэнэ |
| Танигдаагүй event төрөл | Тэр самбарын анхааруулга + дүгнэлт |
| Нэгжээ сэргээж чадаагүй нэгтгэл | Мөн тэнд, хэдэн бичлэг гээгдсэнийг тоогоор |
| Тоо хаанаас гарсан нь ойлгомжгүй | Ур чадвар/даалгаврын modal → `НОТОЛГОО` жагсаалт |

Нотолгоо огт байхгүй бол систем **тэг** гэж хэлнэ. Тоо зохиохгүй, алдаа ч шидэхгүй.

## Гүүрийн гэрээ

Холбогдсон апп бүр ижилхэн JSON нийтэлнэ:

```jsonc
{
  "v": 1,
  "updatedAt": 1787374324442,
  "status": { /* апп юу ч хүсвэл — бид бүтнээр нь хадгална, тайлбарлахгүй */ },
  "events": [
    {
      "id":     "gym:2026-08-21:push",   // ЗААВАЛ. Давхардлын хамгаалалт үүн дээр тогтоно
      "at":     1787374324442,           // ms
      "type":   "workout.completed",
      "value":  1,
      "detail": "Push day",
      "data":   { "volumeKg": 4200 }     // заавал биш: бодит нэгж энд
    }
  ]
}
```

**Хувилбарууд.** `BRIDGE_VERSIONS = [1, 2]`. v2 нь v1 дээр event бүрд `date`
(орон нутгийн хуанлийн өдөр) талбар нэмсэн бөгөөд өөр юу ч аваагүй — уншигчийн
хувьд бүрэн нийцтэй.

**Голдох нь чимээгүй БАЙХГҮЙ.** Хоёр өөр зүйлийг ялгана:

| Юу болов | Хариу |
|---|---|
| Түлхүүр байхгүй, файл 404, сүлжээ унтарсан | **чимээгүй алгасна** — апп суугаагүй, эвдрэл биш |
| Түлхүүр байгаа мөртлөө уншигдахгүй (хувилбар, JSON, бүтэц) | `integrations[app].feedError`-д бүртгэж, Integrity самбарт `УНШИГДАХГҮЙ` гэж шалтгаантай нь гаргана |

Энэ ялгаа яагаад хэрэгтэйг санах нь зүйтэй: Bigu гэрээгээ v2 болгож
шинэчлэхэд энэ тал v1-ийг л хүлээж авдаг хэвээр байв. Сар турш хийсэн
давтлага чимээгүй голдож, дэлгэц дээр зүгээр л "ХОЛБОГДООГҮЙ" гэж
харагдаж байсан — өөрөөр хэлбэл "апп суулгаагүй"-тэй ялгагдахгүй. Гэрээний
хувилбар зөрөх нь **эвдрэл** бөгөөд эвдрэл нь ил байх ёстой.

**Гурван төрлийн хүргэлт, нэг гэрээ:**

- `kind: "local"` — ижил origin дээрх апп `localStorage`-д бичнэ.
- `kind: "fetch"` — repo дотор commit хийгдсэн JSON. GitHub `localStorage` руу
  бичиж чадахгүй тул түүний нотолгоо Action-аар дамжиж `data/github.json`
  болж ирдэг.
- `kind: "self"` — **гадны апп биш**. Хэрэглэгч өдрийн даалгавраа тэмдэглэхэд
  энэ апп өөрөө бичдэг. Уншиж авах фийд байхгүй тул `syncAll()` алгасна.

## Өдрийн даалгавар

Даалгавар бүр `metricId` зарлаж болно. Түүнээс хойш хоёр зам:

```
                     тэр метрикт ӨНӨӨДӨР нотолгоо ирсэн үү?
                                   │
                 тийм ─────────────┴───────────── үгүй
                   │                                │
        ✓ НОТЛОГДСОН                        дарж болно
        (дарах юм байхгүй)                        │
        Gym → 4,200 kg                    ◈ ӨӨРӨӨ МЭДЭЭЛСЭН
                                          self.checkins → DISCIPLINE
```

Дасгал хийгээд Gym аппаа нээхэд "Workout" даалгавар **өөрөө** ✓ болно — хэн ч
дарах шаардлагагүй. Харин "2 литр ус уух" гэдгийг ямар ч апп мэдээлдэггүй тул
түүнийг дарж бүртгэнэ, тэр нь `DISCIPLINE`-д л ордог.

Тэмдэглэгээ нь `task.completed` талбараас БИШ, **нотолгооноос** гардаг:
бичлэгийн id нь `self:<taskId>:<өдөр>` тул нэг өдөр нэг даалгавар яг нэг удаа
тоологдож, буцааж авахад яг тэр бичлэг устна. Хуучин өдрийн бүртгэл түүх болж
үлдэнэ — өдөр солигдоход зүгээр л шинэ өдрийн id хайгдана.

Даалгаврыг самбар дээрээс нэмж, хасаж болно. **Хасах нь түүх устгахгүй**:
өмнө нь бүртгэсэн check-in-ууд нотолгоо хэвээр үлдэнэ, учир нь тэдгээр нь
үнэхээр болсон явдал байсан. Жагсаалт бол өнөөдрийн санаа, нотолгоо бол
өнгөрсний баримт — хоёр өөр зүйл.

Товч, гар хоёулаа ажиллана (`Enter` / `Space`): DISCIPLINE-ыг хөдөлгөдөг
цорын ганц удирдлагыг зөвхөн хулганаар хүрч болдог байлгах нь бүхэл нэг
тэнхлэгийг нууж байгаатай адил.

## Өргөтгөх

### Шинэ апп холбох

`bridge.js` → `BRIDGE_SOURCES`-д **нэг мөр**:

```js
{ app: "duolingo", kind: "local", key: "duo:bridge", label: "Duolingo", hex: "#58cc02" }
```

Өөр код бичихгүй. Синк, хадгалалт, "Connected" карт, бүрэн бүтэн байдлын
самбар — бүгд өөрсдөө дагана.

### Шинэ метрик нэмэх

`status.js` → хоёр хүснэгтэд мөр нэмнэ:

```js
// Event-ийн төрөл юу гэсэн утгатайг ТАЙЛБАРЛАДАГ цорын ганц газар
"duolingo:lesson.done": {
    metric:     "duo.xp",
    amount:     e => num(e.value),        // түүхий бичлэгээс
    fromRollup: b => num(b.valueSum)      // нэгтгэсэн хувингаас, ижил нэгжээр
},

// Метрик өөрөө: нэр, нэгж, аль атрибутад харьяалагдах, 30 хоногийн зорилт
"duo.xp": { label: "Duolingo XP", unit: "xp", attr: "MIND", target30: 3000 }
```

Ур чадвар болон даалгаврын формын "Нотолгооны эх сурвалж" сонголт нь энэ
бүртгэлээс баригддаг тул тэнд ч юу ч засахгүй.

`fromRollup` нь `null` буцаах эрхтэй = *"энэ хувингаас бодит нэгжийг сэргээх
аргагүй"*. Тэр үед 0 нэмэгдэнэ, **гэхдээ чимээгүй биш**: `overall.rollupGaps`-д
бүртгэгдээд Аналитик таб дээр хэдэн бичлэг гээгдсэнийг тоогоор хэлнэ.

## Нотолгоог алдахгүй байх

Систем нотолгоог "цорын ганц үнэн" гэж зарладаг. Тэгвэл түүнийг ганц
браузерын `localStorage` дотор, ганц хуулбартай байлгах нь тэр зарлалыг
хоосон болгоно. Үйлдвэрлэгч аппууд ердөө **сүүлийн 50 event**-ээ хадгалдаг
тул устсан бичлэг **эргэж ирэхгүй**.

### Гаргах / сэргээх

`НОТОЛГОО ЭКСПОРТЛОХ` нь бүх датаг JSON файл болгон татна. `НӨӨЦӨӨС СЭРГЭЭХ`
нь түүнийг буцааж уншина — **нэгтгэж**, дарж бичихгүй:

| Юу | Хэрхэн нийлдэг | Яагаад |
|---|---|---|
| Түүхий бичлэг | `id`-гаар нэгтгэнэ | id тогтвортой тул давхардал үүсэхгүй |
| `prunedBefore`-оос хуучин | **алгасна** | тэр event аль хэдийн хувин болсон — оруулбал хоёр удаа тоологдоно |
| Нэгтгэсэн хувин | `count` илүү ихийг нь авна | нэмбэл давхар тоолно; илүү ихийг харсан тал нь бүрэн |
| Жагсаалт, ангилал | файлынхаар солино | жагсаалтыг дахин бичихэд амархан, нотолгоог сэргээх аргагүй |

Хувин нэгтгэх дүрэм нь **дутуу тоолж магадгүй** (хоёр төхөөрөмж өөр өөр event
харсан бол). Тэр нь зориуд: дутуу тоолох нь давхар тоолохоос үргэлж дээр —
систем тоо зохиодоггүй.

### Хоёр өөр "цэвэрлэх"

| Товч | Юу устгах | Сэргээгдэх үү |
|---|---|---|
| `ЖАГСААЛТ ЦЭВЭРЛЭХ` | Даалгавар, ур чадвар, ангилал, өдрийн жагсаалт | Нотолгоо **хэвээр** |
| `НОТОЛГОО ХАМТ УСТГАХ` | Бүгд | **Үгүй** — тоог нь нэрлэсэн хоёр баталгаажуулалт асууна |

Өмнө нь ганцхан RESET товч байсан бөгөөд тэр нь нэг `confirm()`-ын цаана бүх
түүхийг үүрд устгадаг байв.

### Хадгалалтын тааз

4 эх сурвалж × 5000 түүхий бичлэг ≈ 3–4MB, `localStorage` нь ~5MB. Өөрөөр
хэлбэл "хэзээ ч хаяхгүй" гэсэн бодлого тааztай **зайлшгүй мөргөлдөнө**.
`setItem` унахад `saveWebData()` түүнийг quota алдаа гэж таньж, Integrity
самбарт **ил анхааруулга** гаргана — эс тэгвээс шинэ нотолгоо чимээгүй
алдагдаж, дэлгэц дээр зүгээр л "тоо буурсан" мэт харагдана. Гарц нь:
экспортлох → нотолгоо хамт устгах → шаардлагатай бол файлаа сэргээх.

## Нотолгооны хадгалалт

Бичлэгийг **хэзээ ч зүгээр хаяхгүй** — дээд давхаргын бүх тоо түүнээс
гардаг тул хаях нь түүхийг устгахтай адил.

```
шинэ бичлэг ──► evidence[]  ──180 хоног──►  rollups["YYYY-MM"][type]
               (түүхий, өдрийн              { count, valueSum, dataSums,
                нарийвчлалтай)                firstAt, lastAt }
```

`dataSums` нь `event.data`-гийн **тоон талбар бүрийн нийлбэр**. Түүнгүйгээр
`data.volumeKg` дээр тулгуурладаг метрик (дасгалын кг) нэгтгэгдмэгц мөнхөд
0 болж хувирдаг байсан. Гүүр талбарууд юу гэсэн утгатайг мэдэхгүй хэвээр —
зөвхөн "тоо мөн үү" гэдгийг шалгана; утгыг нь тайлбарлах нь `status.js`-ийн ажил.

`rollups`-ыг **хэзээ ч устгахгүй**. `prunedBefore` нь зөвхөн өсдөг — эс тэгвээс
нэгтгэгдсэн event дахин "шинэ" мэт орж ирнэ.

## Хөгжүүлэх

Build алхам байхгүй, хамаарал байхгүй. Энгийн статик файлууд.

```bash
# Дотоод сервер (bridge.js data/github.json-ыг татдаг тул file:// болохгүй)
python3 -m http.server 8000

# Тест — зөвхөн Node хэрэгтэй
node tests/run.js
```

Тест нь нотолгооноос тоо гаргах болон нотолгоо хадгалах давхаргыг хамарна.
Тэр хоёрын дүрэм өөрчлөгдөхөд **бүх түүх дагаж өөрчлөгддөг** тул алдаа нь
чимээгүй бөгөөд хожим эргэж баригдахгүй — тиймээс л тэдэнд тест бий.
